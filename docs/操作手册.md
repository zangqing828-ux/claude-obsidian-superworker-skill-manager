## 快速开始

### 第一次使用

#### 1. 验证环境

```bash
# 检查 Claude Code
claude --version

# 检查 Obsidian
obsidian --version

# 检查 Python
python3 --version
```

#### 2. 安装技能

```bash
# 进入项目目录
cd CC+OB-open

# 复制技能
cp -r skills/* ~/.claude/skills/
```

#### 3. 配置 Vault

编辑 `~/.claude/skills/personal-obsidian-workflow/SKILL.md`：

```markdown
主 Vault: ~/Documents/MyKnowledgeBase
```

#### 4. 测试使用

在 Claude Code 中发送：

```
创建一个测试文档，标题是"Hello Claude Code + Obsidian"
```

预期结果：在 Vault 中创建格式正确的 Markdown 文件

## 核心功能

### personal-obsidian-workflow

**功能**：个人 Obsidian 工作流配置

**特性**：
- 自动文档分类
- 智能文件搜索
- 文件命名规范
- 工作流规则

### skill-dashboard-generator

**功能**：技能状态仪表盘生成器

**特性**：
- 自动扫描所有技能
- 提取技能元数据
- 生成可视化仪表盘
- 支持多种输出格式

## 使用示例

### 示例 1: 创建产品需求文档

**你的输入**：

```
创建一个产品需求文档，主题是"移动端笔记应用 APP"
```

**Claude Code 自动**：
1. 识别为 PRD（产品需求文档）
2. 选择文件夹 `01-项目规划/`
3. 创建文件 `PRD-移动端笔记应用-2026-02-11.md`
4. 填充标准 PRD 模板内容

### 示例 2: 创建技术决策记录

**你的输入**：

```
创建一个 ADR，主题是"选择 PostgreSQL 作为主数据库"
```

**Claude Code 自动**：
1. 识别为 ADR（架构决策记录）
2. 选择文件夹 `03-架构设计/`
3. 创建文件 `ADR-2026-02-11-数据库选择.md`
4. 填充 ADR 模板内容

### 示例 3: 生成技能仪表盘

**在终端运行**：

```bash
python3 ~/.claude/skills/skill-dashboard-generator/scripts/generate_full_markdown.py
```

**在 Claude Code 中**：

```
生成技能仪表盘
```

**结果**：
- 在 Vault 中创建 `00-技能状态.md`
- 包含所有已安装技能的列表
- 按分类组织（开发工具、工作流、代码质量等）
- 包含 wikilink，可直接跳转到技能文件

### 示例 4: 搜索文件

**你的输入**：

```
搜索标题包含"数据库"的文件
```

**Claude Code 返回**：

```markdown
## 搜索结果：数据库

找到 2 个文件：

### 03-架构设计/
- [[ADR-2026-02-11-数据库选择]] - 选择 PostgreSQL 作为主数据库

### AgenticDAM文档/
- [[数据模型设计]] - DAM 系统数据模型
```

## 高级配置

### 自定义文档分类

编辑 `personal-obsidian-workflow/SKILL.md`，修改分类规则：

```markdown
| 文件夹编号 | 文件夹名称 | 存放的文档类型 | 触发关键词 |
|-----------|-----------|--------------|-----------|
| `01-产品/` | 产品文档 | PRD、用户故事 | PRD, 产品, 用户故事 |
| `02-设计/` | 设计文档 | UI/UX 设计 | 设计, UI, UX |
```

### 自定义命名规范

修改 `personal-obsidian-workflow/SKILL.md`：

```markdown
| 文档类型 | 命名格式 | 示例 |
|---------|---------|------|
| PRD | `PRD-{项目}-{日期}.md` | `PRD-笔记应用-2026-02-11.md` |
| ADR | `ADR-{YYYYMMDD}-{描述}.md` | `ADR-20260211-数据库.md` |
```

### 配置外部项目符号链接

在 Vault 中创建符号链接：

```bash
# 项目 A
ln -s /path/to/project-a/docs "{VAULT}/项目A文档"

# 项目 B
ln -s /path/to/project-b/docs "{VAULT}/项目B文档"
```

## 最佳实践

### 1. 文档创建流程

```
1. 明确需求 → 2. Claude Code 创建 → 3. Obsidian 查看
```

- 在 Claude Code 中清晰描述需求
- 让 Claude Code 自动选择正确的文件夹和格式
- 在 Obsidian 中查看和浏览

### 2. 技能维护

```bash
# 定期更新技能
cd ~/.claude/skills/personal-obsidian-workflow
git pull origin main

# 或重新复制最新版本
cp -r CC+OB-open/skills/* ~/.claude/skills/
```

### 3. 仪表盘更新

```bash
# 每次添加新技能后运行
python3 ~/.claude/skills/skill-dashboard-generator/scripts/generate_full_markdown.py

# 或在 Claude Code 中
"更新技能仪表盘"
```

### 4. 备份和同步

- 使用 Git 版本控制 Vault
- 定期备份技能目录
- 使用 Obsidian Sync 或第三方云服务

## 常见使用场景

### 场景 1: 日常笔记

**工作流**：

1. 在 Claude Code 中说："快速记录一下这个想法：..."

## 故障排除

### 问题 1: 文档创建在错误位置

**原因**: 分类规则不匹配

**解决方案**:

1. 明确指定文件夹："在 02-技术文档/ 中创建..."
2. 更新 `personal-obsidian-workflow/SKILL.md` 中的关键词

### 问题 2: 技能未被识别

**原因**: 文件路径或名称不正确

**解决方案**:

```bash
# 检查文件是否存在
ls ~/.claude/skills/personal-obsidian-workflow/SKILL.md

# 检查大小写（必须是 SKILL.md，不是 skill.md）
```

### 问题 3: 仪表盘不完整

**原因**: 技能路径扫描不完整

**解决方案**:

```bash
# 手动扫描所有技能
find ~/.claude/skills -name "SKILL.md" -type f

# 检查结果数量是否正确
```
